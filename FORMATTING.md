# 🎨 VoxiHost Blog Content Style & Formatting Guide

This document defines the layout, metadata, shortcodes, and design patterns required for articles published on the **VoxiHost** blog. Following these rules ensures that your posts render correctly, perform well, and look stunning.

---

## 📋 1. YAML Frontmatter Requirements

Every article must start with a YAML frontmatter block containing the required properties:

```yaml
---
image: /assets/images/blog/pl/aktualizacja-wersji-php-linux/og-image.png
title: Jak zarządzać i aktualizować wersje PHP na Linux (Ubuntu i Debian)
description: Kompletny przewodnik do bezpiecznej instalacji, aktualizacji i zarządzania wieloma wersjami PHP i PHP-FPM na swoim serwerze Linux.
date: '2026-03-25'
translationKey: manage-update-php-versions-linux
category: Poradniki
tags:
  - php
  - ubuntu
  - linux
status: published
locale: pl
author:
  name: VoxiHost Team
  link: https://voxihost.pl/
contributors:
  - danielmarszalkowski
---
```

### Required YAML Properties
*   **`image`**: Path to the article's hero and OG (social preview) image. **Generated by the VoxiHost team** — leave as the placeholder in your draft, we will set the correct path before publishing.
*   **`title`**: Compelling, SEO-friendly headline.
*   **`description`**: A short summary of the article (1-2 sentences) used in index pages and meta description tags.
*   **`date`**: Publication date in `YYYY-MM-DD` format.
*   **`translationKey`**: A unique string shared between the English and Polish versions of the same article (used for language switching).
*   **`locale`**: Language code (`en` or `pl`).
*   **`category`**: The primary topic/section. Valid values: `Tutorials` / `Poradniki` (how-to guides), `Updates` / `Nowości` (announcements), `Comparisons` / `Porównania` (technology comparisons).
*   **`status`**: Use `draft` when submitting. The team will change it to `published` after approval.
*   **`author`**: Object defining the primary author:
    ```yaml
    author:
      name: "VoxiHost Team"
      link: "https://voxihost.pl/"
    ```
*   **`contributors`**: Array of GitHub usernames who contributed to this post. Your GitHub profile image and link will be automatically generated from this:
    ```yaml
    contributors:
      - danielmarszalkowski
    ```

## 🖼️ 2. Images & Responsive Shortcodes

To keep pages lightweight and fast-loading, **never use native Markdown image syntax** (`![alt](url)`) in paragraphs. Instead, use our custom Nunjucks responsive image shortcode:

```jinja
{% image "[src]", "[alt_text]", "[sizes]", "[class]", [eager] %}
```

### Shortcode Parameters
1.  **`src`** *(String)*: Webroot path to the image, formatted as: `/assets/images/blog/<lang>/<post-slug>/<image-name>.<ext>`
2.  **`alt_text`** *(String)*: Descriptive text for accessibility and SEO.
3.  **`sizes`** *(String, optional)*: Responsive width hints. Standard value: `"(max-width: 768px) 100vw, 800px"`.
4.  **`class`** *(String, optional)*: Additional CSS styling classes.
5.  **`eager`** *(Boolean, optional)*: Defaults to `false`. Set to `true` ONLY for above-the-fold hero images.

### Asset Storage & Path Mapping
*   **Local Storage Path**: Save all image files inside the `images/` directory of the post (e.g. `src/published/pl/aktualizacja-wersji-php-linux/images/H1.png`).
*   **Markdown Reference**: Map this path to the web production prefix `/assets/images/blog/<lang>/<post-slug>/` as shown below:
    ```jinja
    {% image "/assets/images/blog/pl/aktualizacja-wersji-php-linux/H1.png", "Uruchamianie instalacji PHP", "(max-width: 768px) 100vw, 800px" %}
    ```

## 💎 3. Styling & Brand Patterns

Our front-end rendering engine automatically looks for specific elements and enhances them:

### 🅰️ Auto-Coloring Anchor Links
To keep Markdown clean, the engine styles links dynamically based on their destination URLs. Use standard Markdown links; the site will auto-color them:

*   **Premium VPS Links** (target contains `/premium-vps/`): Styled in **Amber** (`text-amber-300`).
    *   *Example:* `[Premium VPS plans](/premium-vps/)` or `[nasz cennik Premium VPS](/pl/premium-vps/)`
*   **Budget VPS Links** (target contains `/budget-vps/`): Styled in **Sky Blue** (`text-sky-300`).
    *   *Example:* `[Budget VPS plans](/budget-vps/)` or `[tani hosting VPS](/pl/budget-vps/)`
*   **Shield/DDoS Links** (target contains `/shield/`): Styled in **Emerald Green** (`text-emerald-300`).
    *   *Example:* `[Shield protection](/shield/)` or `[ochronę DDoS Shield](/pl/shield/)`

### 🏷️ Brand Logo Wrapping
Always format the brand name as follows in headings and paragraphs to render the correct design tokens:
```html
<span class="text-white">Voxi</span><span class="text-amber-300">Host</span>
```
*Note: Do not wrap the brand name when it appears in code blocks, systemd files, metadata fields, or image alt tags.*

### 🔍 Image Zooming (Lightbox)
Any image inserted outside lists or figures automatically gains hover effects (`cursor-zoom-in`). Clicking it opens a beautiful, glassmorphic modal displaying the image in full screen.

### 📋 Code Blocks
Fenced code blocks (using triple backticks ```) automatically render with:
*   Copy to clipboard button (shows dynamic copy/success states).
*   Beautiful syntax highlighting.
*   Clean terminal styling.

### 💬 Blockquotes and Callouts
Use blockquotes (`>`) to emphasize warnings or tips. They are styled with a solid left-accent border:
```markdown
> **Secure SSH:** Changing the default port from 22 to a custom port reduces automated scan attempts...
```

## ❌ Common Mistakes

This section shows the most frequent errors contributors make. Check your article against these before submitting a PR.

### 1. Using native Markdown image syntax

❌ **Wrong** — the image will not be responsive, will not lazy-load, and will not get the zoom lightbox:
```markdown
![My screenshot](images/step1.png)
```

✅ **Correct** — always use the Nunjucks shortcode with the full web path:
```jinja
{% image "/assets/images/blog/<lang>/your-article-slug/step1.png", "Description of what is shown in step 1", "(max-width: 768px) 100vw, 800px" %}
```

---

### 2. Wrong author format (string instead of object)

❌ **Wrong** — this is a plain string and will not render the author link:
```yaml
author: "VoxiHost Team"
```

✅ **Correct** — always use the structured object form:
```yaml
author:
  name: VoxiHost Team
  link: https://voxihost.pl/
```

---

### 3. Unformatted brand name in body text

❌ **Wrong** — VoxiHost will render as plain text with no brand styling:
```markdown
Thank you for choosing VoxiHost!
```

✅ **Correct** — wrap with HTML spans (outside of code blocks and alt text only):
```html
Thank you for choosing <span class="text-white">Voxi</span><span class="text-amber-300">Host</span>!
```

---

### 4. Missing translationKey

❌ **Wrong** — each article must share a key with its paired translation:
```yaml
# no translationKey
locale: en
```

✅ **Correct** — both EN and PL versions must have the same `translationKey` value:
```yaml
# In the EN file:
translationKey: secure-ssh-ubuntu-debian
locale: en

# In the PL file:
translationKey: secure-ssh-ubuntu-debian
locale: pl
```
This is what powers the 🇬🇧 / 🇵🇱 language switcher button on the article page.

---

### 5. Submitting directly to `src/published/`

❌ **Wrong** — `src/published/` is managed exclusively by the VoxiHost editorial team:
```
src/published/en/my-new-article/   ← don't submit here
```

✅ **Correct** — always submit new articles to the drafts folder:
```
src/drafts/en/my-new-article/      ← submit your PR here
```
After review and approval, the VoxiHost team will move your article to `published/` and compile the ZIP packages.
